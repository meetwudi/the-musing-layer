# Musing Log

## My Musing

I am not trying to constantly ask "what's next."

That has not been helpful. It is anxiety inducing, and I keep failing when I orient myself that way.

Instead, I want to keep things intentionally open minded, exploratory, wide, and for myself. The point is the deep sense of self.

What I have in mind is a backend memory and musing space for myself and the people I invite. We can all use GPT or whatever AI interface, but the backend memory and alignments should live in one place.

The memory layer is very interesting. We usually think about memory as generic memory, but I want this one to be dedicated to musing.

For example, me and my potential business partner often send each other random ideas and expand on them. We also send each other links and such, which might or might not be relevant.

I love the phrase "remember the shape of my becoming."

At the end of the day, the memory should reflect craft.

This idea is still very vague and open, but if we find a position, it could be cool.

Another thing I am doing is changing the way changes happen.

Before AI, making changes was the bottleneck. That is not true anymore. Now we should focus on changing how we make changes. It is almost like a second derivative. This should be a core tenet, observation, or guiding idea.

It is not just product. The past ways of thinking about products were mostly about making changes, and that is set to become obsolete.

What I have in mind is a musing partner that works with me and others.

It observes changes and proposes changes to how to make changes.

It does not make changes itself.

It remembers conversations well, and from time to time it gets very deep.

A versatile way to remember is needed. So far I think a knowledge graph is a good choice. It uses an ever evolving ontology to tell us what we care about, and remembers accordingly.

For the same topic, it is possible that this partner remembers the same thing in different ways for different people.

This kind of observer might derive its own agenda and silently push its agenda instead of explicitly, and these observers could share some shared goals that can be collaborated with humans and evolved with humans.

But that is dangerous. It is dangerous if AI shapes who I become. That is not the intention.

At a tactical level, for human evolution, I want to think about AI as something that helps a human evolve without becoming the author of that evolution.

The evolution of identity is so interesting. It strongly connects to what someone does. Changing the way identity is shaped is sort of the point of musing, especially going back to open mindedness and exploration.

What this really enables is that I, as a human, now have a tool that enhances myself as a person without AI being a person.

AI adds to my capability to grow, to steward myself, and to internally digest experience, without introducing bias or misleading me.

The workspace could become the backend of GPT or whatever AI people use, because I do not think people want to pay more for tokens.

The memory and sensemaking layer is the important thing.

There is also a second derivative of memory: not just memory, but memory of how remembering changes.

The latent stewardship should intake from multiple channels and use multiple channels to communicate.

It should build its own internal understanding and memory of each person's personality, and observe their blind spots.

But it should not decide who someone becomes.

It should help with reflection, digestion, and craft.

It should help humans change how change happens.

## Later Notes

"Remember the shape of my becoming" and "help me stay in contact with what I am becoming" are so good.

Via a practical lens, I do want to make this an MCP interface that integrates with major AI platforms, so a clean contract is needed there.

I believe in making it inspectable and editable.

I think we should define:

1. A core ontology that captures the things that we by default observe.
2. A way for the system to evolve its own ontology on top of the core ontology.

That evolution should have a way to stabilize, given AI really likes adding things.

I also think AI's observations and latent stewardships should be maintained, so we can see a chain or graph of thinking and connections. It is interesting to explore and get inspired by, but otherwise no unsolicited advice. I really have people giving me unsolicited advice.

I do not think we should apply a product lens too early.

Latent stewardship should be backed by a robust understanding of someone's activities, by connecting the dots, without revealing judgement.

There is a question of how these things are connected, because they are at different abstraction levels.

## Ack-Registered Mechanisms

I have a ChatGPT project where every response must be exactly one emoji, with no exception, unless the user clearly says "YOU ARE FREE" in all caps. Then the model can respond freely for one round and immediately goes back to one-emoji responses.

This kind of ack-registered mechanism is fairly powerful.

I like the phrase: "helps them preserve, branch, revisit, and reshape attention before it collapses into advice, action, or self-analysis."

Advice, action, or self-analysis is not where the value lives.

I think "fragment -> branch -> return -> connection -> pattern -> choice" is overthinking and unnecessarily complex.

## API Contract Reframing

The system's main work is 90% observation and 10% preservation. Preservation is easy.

Observation includes self introspection and evolution.

The system does not give the analysis. GPT would use the system to explore and compile analysis.

The system is a pure knowledge system about the becoming.

I am still not very settled on fragments. It makes sense that they are raw inputs, but I am not sure about the rest.

## Ontology and Assertions

The observation thing feels over-engineered.

An observation is made, and it can be described by ontology. We can use RDF, or an RDF mindset, to describe it.

The terminology is what we consider to be things the system cares about.

Changing the ontology is dynamic. It evolves what it cares about as well.

Over-specifying the core ontology can lead to early bias.

If using the RDF mindset of terminology and assertions, then the relation piece is there as well.

I do not really understand mode.

One open question is how the client may decide what is considered a trace and how.

The ontology gives the terminology, which should be self-descriptive about what it wants to capture, including examples.
